## ЗОНА 2 — ЗАДАЧИ

### 2.1 Канбан + создание (TasksPage + tasks.ts + tasks.py) — 🔴 role-гейтинг бэкенда

- Фронт корректно прячет кнопку «Новая задача» от ТП (`TasksPage.tsx:512` `{isManager && ...}`, комментарий PO 2026-06-28). Но **API открыт**: ТП может создать задачу прямым POST `/api/v1/tasks`. Владелец явно говорил: создание задач — функция руководителя. Фикс на UI есть, на бэке — нет.
- Для контраста: `generate-learning` (`:722`) и `generate-practical` (`:854`) ПРАВИЛЬНО гейтятся `require_role(supervisor+)`. Только ручной `create_task` забыли.

**Несогласованность кнопки «Генерация обучения»:**
- `TasksPage.tsx:481` кнопка «Генерация обучения» показана ВСЕМ (вне `isManager`), а бэкенд `generate-learning` требует supervisor+ (`:722`). → ТП нажмёт → 403 → тост ошибки (`handleGenerate` catch → `tasks.generate.error`). Кнопку либо скрыть для ТП, либо это намеренный «self»-сценарий (scope `'my'`), но тогда бэк её для sales_rep всё равно отвергнет. Баг.

**Создание задачи через UI неполноценно:** модалка создаёт задачу БЕЗ исполнителя (`handleCreate` `:432` шлёт только title/description/priority/status, нет `assignee_id`). → руководитель не может назначить задачу подчинённому из этой модалки; задача создаётся «ничья». Уведомления ассайни (`tasks.py:391`) не сработают. Похоже на недоделанную фичу.

**Прочее:**

### 3.3 Role-гейтинг вкладок (TeamHubPage) — 🔴 баг иерархии ролей
- `ROLE_HIERARCHY` (`TeamHubPage.tsx:16`): `regional_manager: 2`, `admin: 3`, `commercial_dir: 4`.
- **Противоречит канону RBAC** (`api-conventions.md`): `commercial_dir > regional_manager > admin > supervisor`. Здесь РМ (=2) НИЖЕ admin (=3).
- Последствие: **regional_manager (РМ) видит только вкладку «Управление»** (isSupervisorPlus), но НЕ видит «Состав»/«Админ»/«Структуру» (требуют `isAdminPlus`, level≥3). То есть РМ — лицо выше админа по RBAC — лишён структуры и состава. Реальный функциональный баг доступа.
- Также `regional_manager: 2` равен `supervisor: 2` — РМ приравнен к СВ по уровню.
