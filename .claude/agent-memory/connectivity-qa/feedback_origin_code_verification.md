Вывод вида «этой формулы/колонки/эндпоинта нет» делать только после
`git clone --depth 1` бэкенда в scratchpad и локального grep по рабочей копии.

**Why:** `gh api "search/code?q=...+repo:..."` на приватном
`traektoriya-rag-backend` вернул `total_count: 0` для строки, которая на самом деле
встречается в 10 файлах (прогон 2026-07-27). GitHub Code Search приватные репо
индексирует неполно — ноль от него означает «не знаю», а не «нет». Ровно такая
ложная уверенность уже дважды порождала ложные тревоги в отчётах (см. готчу
каталога про локальное дерево).

**How to apply:** точечный файл — `gh api .../contents/<path> --jq .content | base64 -d`
(быстро); любой поиск «где ещё используется / кто пишет в это поле» — только клон + grep.
Клон занимает ~1 минуту и живёт в scratchpad до конца прогона. Отдельно полезно:
grep на **присваивание** (`field =`, `field=`) отдельно от чтения — так за один
запрос видно, что колонка read-only и живого писателя у неё нет.
